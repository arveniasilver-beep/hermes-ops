# HERMES / Sovereign Uctan Uca Devir Denetimi

Tarih: 18 Temmuz 2026  
Kapsam: Handoff butunlugu, kaynak-kod iddialari, test/build, runtime, model
routing, backup, secret/data ve version-control guvenligi.

## Sonuc

Devir sistemi genel olarak guclu ve projeyi devralmak icin yeterlidir; fakat
`tam yeniden uretilebilir baseline` degildir. Bir sonraki teknik lider projeyi
sifirdan kesfetmek zorunda kalmaz, ancak kod yazmaya baslamadan once asagidaki
P0 aciklari kapatmalidir.

## P0 Bulgular

### 1. Version-control baseline yok

- Sovereign kaynak klasorunde `.git` yoktur.
- HERMES deposunda 6.303 dosya untracked bulundu; `.git` vardir fakat gecerli
  `HEAD` veya ilk commit yoktur (`master` dogmamis dal adidir).
- `runtime/sovereign-audit-data` icinde identity, chat, event ve task JSON verisi
  vardir; onceki `.gitignore` bunlari dislamiyordu.
- `backups/`, audit data, gateway-state alani ve runtime screenshot'lari bu
  denetimde ignore edildi. Sonrasinda 6.205 kaynak/kontrol dosyasi untracked
  kaldi. Hicbir dosya stage/commit edilmedi.

Kabul: secret/user data disarida kalan kontrollu file listesi, ilk commit/tag ve
rollback dokumani. `git add .` kullanilmamali; staged liste elle incelenmelidir.

### 2. Dedicated model gateway topolojisi tekrar uretilemiyor

- `sovereign-mimo`, `sovereign-deepseek`, `sovereign-hermes` profil dizinleri var.
- 17 Temmuz'da 8642/8643/8644 topolojisi canli kabul edildi.
- Bugunku kalici Sovereign `.env` yalniz DeepSeek 8643'u tanimliyor.
- MiMo ve restricted Hermes icin repo-owned install/start/stop/status scripti,
  receipt ve restart acceptance yok.

Kabul: idempotent lifecycle scripti; secret degerini kopyalamadan profil health,
route/model ve port dogrulamasi; reboot/restart sonrasi provider acceptance.

### 3. Temiz test baseline'i yeniden uretilmedi

- `pnpm typecheck`: 11 workspace projesi gecti.
- Hermes routing-report testi: 1 gecti.
- `pnpm test`: MCP Bridge'de Windows `ENOBUFS` nedeniyle tamamlama yok.
- MCP testi sabit 4601 portunu kullanir ve erken network hatasinda process/listener
  birakabilir.
- Minimal Node loopback server da `ENOBUFS` urettigi icin ilk hata OS/network
  kosuludur; teardown sizintisi ise test fixture'i problemidir.
- Build tekrari yeni sandbox izni nedeniyle external kaynakta `EPERM` aldi;
  kaynak compile regresyonu olarak yorumlanamaz.

Kabul: temiz Windows oturumu, her durumda kapanan dinamik/deterministik test
fixture'i, `>=119` test, 11/11 typecheck, production build ve izole smoke E2E.

### 4. Runtime kapali

- Docker daemon kapaliydi.
- 4310-4319, 4320-4321, 4601 ve 8642-8644 portlarinda listener yoktu.
- Bu nedenle 17 Temmuz canli kabul kaydi bugunku health iddiasi degildir.

Kabul: izole data dir ile runtime start/status/stop receipt'i; chat, public-web
task, Computer frame/takeover/release ve artifact export smoke akisi.
